Mwangaza School

School management for the DR Congo, built to keep working without internet.

Students and families, fees in US dollars and Congolese francs, a cash desk that prints receipts, unpaid-fee follow-up, grades, deliberations and report cards, and a portal where parents follow payments on their phone. Designed with a technical school in Goma.

Visit mwangazaschool.com

Role · Product, design, engineering and operations

What I did

  • Designed every screen as a mockup first, then built the Django API and the React applications for staff and parents.
  • Offline-first cash desk: each device numbers its own receipts and every write is idempotent, so nothing is counted twice when the network returns.
  • School data isolated twice, by the application and by PostgreSQL Row Level Security, with an audit trail on payments, grades and roles.
  • Deployed and monitored in production, with off-site backups and uptime checks.

03 — Highlights

Problems I have solved

The constraints of the field shape the engineering: unstable networks, two currencies, shared phones and modest servers.

Mwangaza

Receipts without a server

A school cash desk keeps taking payments during network cuts. Receipts are numbered on the device and synchronised with idempotent writes when the connection comes back.

Mwangaza

Money without rounding errors

Amounts are stored as integers, in cents and francs, with an explicit exchange rate. Payments are immutable: a correction is a new record, never an edit.

Mwangaza

Many schools, one database, no leaks

Every query is scoped to its school, and PostgreSQL Row Level Security enforces it again underneath, with tests that try to read another school's data.

Lab automation

A computer lab that runs itself

An ESP32 handles dual RFID access, occupancy counting, energy metering, daylight-aware lighting and night-time intrusion detection, in eleven firmware modules.

PID control

A controller proven before the board

The PID that drives a DC motor is unit-tested on the computer against a motor model, anti-windup included, before it is flashed to the Arduino.

Edge AI

A neural network on a microcontroller

A 172-parameter model diagnoses motor faults on an ESP32, and a parity test proves that the firmware computes what the model learned in Python.

05 — About

Between circuits and code

My work covers the whole chain: the circuit and its firmware, the signal processing and machine learning that interpret the data, and the web platform people use to operate it, designed for the conditions of the eastern DR Congo. How I work

  • Verify against a reference. Numerical code is checked against analytical results or established libraries, and firmware logic is unit-tested on the host before it reaches hardware.
  • Make the model and the device agree. When an algorithm is trained on a computer and deployed on a microcontroller, a test proves that both compute the same thing.
  • Mockups before code. Every screen is drawn at phone and desktop widths before it is built, with real content from the domain.
  • State limits honestly. Every project says what has been validated and what has not.
